So the way I'm thinking about this is we should split the migration into three phases. First, we stand up the new database schema alongside the old one, without touching any of the existing read paths. Second, we backfill the historical data in batches, probably overnight, so we don't hammer production during business hours. Third, once we've verified the backfill is complete and the checksums match, we cut over the write path and start dual-writing for a week before we retire the old table entirely. The biggest risk here is that backfill job silently dropping rows if the source table gets a schema change mid-migration, so I want someone watching the row counts the whole time, not just checking them at the end.
